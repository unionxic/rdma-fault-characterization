# Review of existing results for the error-propagation analysis (2026-10-06)

Four read-only reviews (`review_20261006/`) went through every result directory again before any
prediction is written:
- `cpu_baseline.md`: harness, cqe_seq, fingerprint_teardown, ack_timeout.
- `gin.md`: NCCL 2.32.3 GIN, proxy and GDAKI, Q4, recovery, S1/S2.
- `nvshmem.md`: NVSHMEM IBGDA stock, the doorbell-record bug, official 3.8.0, FT v1-v2.2, T1.
- `nccl_netib_design.md`: NCCL net_ib Stage 2, transparent_probe, address flap.

Each review recounted headline numbers from the raw data. All headline numbers matched, apart
from the small items listed under "Corrections".

Scope: mlx5-based GPU-initiated RDMA stacks (ConnectX-6, fw 20.43.4100, RoCE v2), with CPU verbs
and NCCL net_ib as host-initiated baselines.

## Layers

| layer | what is observed |
|---|---|
| L0 NIC | QP state, doorbell record, counters |
| L1 CQE | the root-cause CQE the NIC writes, and what the consumer actually reads (root or trailing flush) |
| L2 consumer | what the code polling the CQ derives (proxy thread, device poll) |
| L3 API | what the application receives |
| L4 host | async error value, logs, mailbox |
| L5 teardown | abort/finalize returns or hangs |

Faults: F0 none, F1 local QP to ERR, F2 remote access (invalid rkey), F3 peer QP in ERR (peer
alive), F4 peer killed.

## What the matrix already shows

1. **Information only shrinks going up in every stock stack.** Examples:
   - GDAKI: 4 classes at the root CQE, 2 at the device, and in blocking mode F0..F3 look the same.
   - NVSHMEM GPU handler: 4 classes at L1, 1 class at L3.
2. **Two kinds of added channel.**
   - Some only stop an unnecessary loss: Q4 and FT read the root CQE instead of the trailing flush.
     They can reach at most the L1 partition.
   - Others add information L1 never had: OOB FIN liveness. Only these split F3 from F4.
3. **A fix at one layer can coarsen a higher one.** The DBR fix takes L1 from nothing to 4
   classes, but L3 goes from 2 (hang vs return) to 1 (silent success). Stock device code drops
   the CQE.
4. **Recovery merges on purpose.**
   - S1/S2, T1 and net_ib Stage 2 make recovered faults equal to F0 at L3.
   - The class survives only in logs.
5. **The passive side has no error channel.**
   - One-sided operations give the target no completion.
   - Its async error never fired, and its teardown hangs.
6. **Information that exists but is unused.**
   - GID_CHANGE async events arrive about 3.5 s before RETRY_EXC in 29/29 flap runs.
   - No stack reads them.

## Corrections found (to fix in the docs)

- **Upstream issue draft:** the 3.7 s return with the fix is a silent success at the API, so it
  must not be called "expected". The draft now only says the CQE is generated. Fixed 2026-10-06.
- **Harness:**
  - The fingerprints are not unique: 5/0xf5 is shared by local_qp_err and partial_write.
  - `server_qp_err` is labelled `auto_recoverable=0` in 30/30 rows, which is a labelling bug in
    `probe_client.c`.
  - `retry_proc_kill` is a graceful exit, not a SIGKILL. A real SIGKILL gives 0x88 in 111/270.
- **Root README:**
  - The 6/8/9 classes count equivalence classes, and they come from the old cluster.
  - The 2.8 ms recovery is also from the old cluster; this testbed gives about 0.8 ms.
  - "No effect on other connections" was not re-measured here.
  - The 59.8 s and 9.5 ms figures mix settings.
- **GIN:**
  - "GDAKI teardown clean" holds for rank 0 only; the target's abort hangs.
  - The in-MR overrun "silent loss" has no retained raw data.
  - N30 runs after 09-25 06:45 ran with the leaked firmware command slot, which the N30 doc does
    not mention.
- **NVSHMEM:**
  - The F4 and teardown cells marked "-" in RESULTS.md were measured.
  - The stock README says 364/364; the count is 363. `matrix.csv` has 54 rows, not 51.
  - The 510,028 stale values come from 37/40 runs.
  - "Since v1" is inferred, and the 3.5.x-3.7 scope is from source only.
- **net_ib:**
  - The T12d upper bound was measured to the SUMMARY line; the API error came at 0.24 ms.
  - The flap control was the patched library with the flag off, not the stock binary.
  - The "responder already executed, do not resend" case fired only 5 times, all in flap runs,
    and has no negative control.
  - transparent_probe: the requester's own next_send_psn gave the same value in 20/20.
- **Uncommitted S2/T1:**
  - S2 has placeholder rows and tables from the intermediate build.
  - T1's doc says both 78 s and 93 s for the hold, and the final3 runs are unreported.
  - The FIN rule (any TCP error = peer death) is still in the GIN TS2 code and in the design §8.
