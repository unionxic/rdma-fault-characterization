# s2_close: GIN 투명 복구 2단계 마감

GIN 투명 복구 2단계(여러 연산이 동시에 진행될 때의 복구)에서 남은 항목 가운데 네 가지를, 측정 전에 고정한 예측으로
쟀다(태그 `prereg/gin-s2-close-v1`).

## 무엇을 쟀나

- **최종 빌드 재측정:** 중간 빌드에서만 잰 조건(16, 64 스레드 로컬 QP 오류, 실제 양방향 동시 시작, 지연)을 최종 빌드로 다시 쟀다.
- **받는 쪽 대기 해제:** 사용자 devComm에 통신기의 abort 플래그를 이어, 거절 뒤 받는 쪽 자기 signal 대기가 abort로 풀리는지 봤다.
- **다시 보낼 수 없는 라운드:** get(RDMA READ)이 낀 라운드와 사본 영역을 끈 라운드가 성공으로 나가지 않고 거절되는지 봤다.
- **관리망 소켓 끊김:** 라이브러리의 helper 소켓만 잠시 막아(이 프로세스 소켓에만 건 필터), 지금 정책이 상대를 어떻게 다루는지 쟀다.
- 시행 198회(채점 195회, 포트 충돌로 따로 센 3회는 다시 돌림), 지연 70회, 복구 중 송신을 막는 장치의 미세 시험 14회.

## 결론

- **최종 빌드에서도 투명했다.** 16, 64 스레드 로컬 QP 오류와 실제 양방향 동시 시작이 모두 투명했다.
- **받는 쪽을 깨우는 데는 abort 신호 하나면 된다.**
  - 플래그를 이으니 받는 쪽 `ncclCommAbort`가 1 s 안에 돌아왔다. 플래그를 끄면 14.3 s 걸렸다.
  - abort 전에는 아무것도 풀리지 않았고, 복구 결과와 지연은 그대로였다.
- **실행 여부를 모르는 라운드는 성공으로 내보내지 않았다.**
  - get이 낀 라운드는 READ 표식으로 거절됐고, 조용한 실패는 없었다.
  - 사본 영역을 끄면 거절은 했지만, 예측한 사유가 아니라 그 앞의 범위 검사에서 걸렸다.
- **관리망 소켓이 시간 초과로 닫히면 살아 있는 상대를 잃은 것으로 다룬다.**
  - 끊김 중 상대 QP 오류는 "FIN/RST"로 거절됐다. 실제로는 소켓이 시간 초과로 닫혔고 상대는 살아 있었다.
  - 그 뒤의 복구 가능한 로컬 QP 오류도 "helper 소켓 없음"으로 거절됐다. 받는 쪽은 아무 오류도 받지 못했다.
  - 1 s 끊김은 아무 일도 일으키지 않았다.
- **예측이 틀린 것이 셋이다.**
  - 4 KiB 지연 비용이 0.29 µs로 예측 범위(0.30 µs 이상)에 한 측정 단위 모자랐다.
  - 플래그를 끈 대조의 abort가 15 s보다 일찍(14.3 s) 돌아왔다. 장치 대기가 설정보다 빨리 끝난 것으로 보인다.
  - 사본 영역을 끈 거절의 사유가 달랐다.

## 결과

| 조건 | 결과 | 예측 |

| 16, 64 스레드 로컬 QP 오류(최종 빌드) | 5/5, 5/5 투명 | 맞음 |
| 실제 양방향 동시 시작 | 5/5 투명. 동시 시작 처리를 끄면 4/5 거절 | 맞음 |

| 받는 쪽 abort, 원격 접근 오류 / burst | 862–876 ms / 796–811 ms(각 10/10) | 맞음 |
| 플래그 끈 대조 | 14 275–14 339 ms(5/5) | 틀림(15 s 이상 예측) |
| get이 낀 라운드의 로컬 QP 오류 | 10/10 거절(READ 표식), 조용한 실패 0 | 맞음 |
| 사본 영역을 끈 라운드 | 5/5 거절, 사유는 그 앞의 범위 검사 | 거절은 맞음, 사유는 틀림 |
| 8 s 소켓 끊김 | 4.6 s에 시간 초과로 닫힘, 뒤 장애 10/10 "helper 소켓 없음"으로 거절, 받는 쪽 오류 0 | 맞음 |
| 끊김 중 상대 QP 오류 | 10/10 "FIN/RST"로 거절, 상대는 살아 있음 | 맞음 |

범위는 그 조건의 모든 시행에 걸친 범위다.

## 한계

- abort 플래그는 `ncclCommAbort`만이 아니라 revoke, abort 모드 shrink, 그룹 작업 실패에서도 선다. 그때도 사용자 대기가 풀릴 수 있다.
  풀린 대기는 성공(`ncclSuccess`)을 돌려줘서 커널은 정상 완료와 구분하지 못한다(코드 리뷰, 이 실험의 측정에는 영향 없음).
- 소켓 끊김은 이 프로세스 소켓에만 건 필터라 실제 관리망 장애와 다를 수 있다. 다시 연결하는 기능은 아직 없다.
- 노드 한 쌍, GPU 한 종류, 2 rank다.
