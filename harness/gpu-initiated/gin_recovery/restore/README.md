# gin-restore: 죽은 rank를 예비 프로세스에 되살려 상대를 모르는 대기를 지킨다

GPU가 직접 통신하는 NCCL GIN에서 rank 하나가 죽으면, 살아남은 rank의 "상대를 모르는 대기"(신호가 문턱에 닿기를 기다리는 `waitSignal`)는
앞 실험(gin-remaining, gpu-detect)에서 2 s 뒤 오류로 풀리는 것이 최선이었다. 이 실험은 죽은 논리 rank만 예비 프로세스에 체크포인트와 송신 쪽 로그로
되살려, 생존 rank의 대기가 풀리지도 멈추지도 않고 원래 값으로 끝나게 하는 라이브러리 계층을 만들고, 측정 전에 고정한 예측 21개로 쟀다.

## 무엇을 쟀나

- **바꾼 것(라이브러리).** gpu-detect 계층 위에 복원 계층을 얹었다. 모든 rank가 함께 부르는 복원 시작 함수(켤 수 없으면 모든 rank가 같은 이유의 오류),
  복원 대상 window의 strict ordering 강제, rank마다 고리 하나인 송신 쪽 로그(64 B 항목, 내용 복사 없음), 짝 rank의 호스트 메모리에 두는 증분 체크포인트
  (입력 멈춤으로 절단점을 정함), 죽은 상대를 붙잡는 상태 기계, 예비 프로세스(초기화 기록의 재생, 활성화, 끝점 바꾸기), 다시 보내기 억제. 복원을 쓰는
  프로그램만 빌드 매크로를 켜고, 안 켠 프로그램의 기계어는 앞 라이브러리와 같다.
- **조건.** 노드 둘, GPU 둘, rank 4개(GPU마다 둘), 단계 600개(단계마다 4 KiB put과 신호 둘, 5 ms 간격), 체크포인트 20단계마다. 장애는 단계 중간의 SIGKILL
  (rank 3, 같은 GPU의 rank 1), 체크포인트 멈춤 중의 자기 SIGKILL, 예비 프로세스가 없거나 먼저 없어진 경우, 켤 수 없는 설정 넷, 장애 없음. 대조는 복원이
  없는 앞 라이브러리와 복원을 끈 설정. 비용은 4 KiB와 256 KiB put 지연과 256 KiB 8개 묶음 대역(두 노드, 6 대 6 섞기).
- **잰 것.** 복원과 거절 시행 57회, 회귀 20회, 비용 실행 252회. 다른 에이전트가 채점 코드를 보지 않고 원자료에서 다시 셌다. pilot 셋이 구현 결함 둘과 시험
  장치 결함 하나를 잡아 고친 뒤 사전 등록했다.

## 결론

- **죽은 rank 하나를 되살려 대기를 지켰다.** rank 3 kill 10회, rank 1 kill 5회, 체크포인트 멈춤 중 kill 4회(조건을 채운 시행)에서 생존 rank의 대기가 오류
  없이 붙잡혔다가 원래 값으로 끝났고, 모든 rank의 최종 데이터가 장애 없는 실행과 비트 단위로 같았다. 생존 rank는 되돌아가지 않았고 되살린 rank만 확정
  체크포인트부터 다시 돌았다. 다시 보내기 억제는 통로 60개 모두 정확했다.
- **복원은 0.3–0.4 s에 끝났다.** 죽음 판정부터 복원 완료까지 278–401 ms. SIGKILL된 CUDA 프로세스는 /proc에서 0–126 ms 뒤에야 사라져 예비 프로세스가 그동안
  "나중에"로 답했고, 예비 프로세스의 초기화 재생(0.4 s)은 kill 전에 끝나 있었다.
- **복원할 수 없으면 앞 라이브러리와 같이 fail-fast다.** 예비 프로세스가 없으면 2 s 뒤 degraded로 풀렸고, 등록했으나 없어졌으면 1 s 뒤 fallback, 2 s 뒤
  풀렸다. 켤 수 없는 설정 넷에서는 모든 rank가 같은 이유의 오류를 받았고, 매크로 없는 프로그램은 거절 뒤 fail-fast로 끝까지 돌았다.
- **비용은 로그가 아니라 hold 보내기 길에 있고, 4 KiB에서 한도 10%를 넘었다.** 로그 자체는 0–0.2 µs였고 hold 길이 put마다 1.0–1.5 µs(4 KiB 9–15%,
  256 KiB와 대역 3–6%)였다. 10% 한도는 sunny의 4 KiB 지연에서 틀렸다. 표본 checksum은 묶음 대역을 절반으로, 전부 checksum은 97%를 줄였다(기본값 끔).
  매크로 없는 fail-fast는 앞 라이브러리와 거의 같았지만 sunny 4 KiB에서 0.06 µs(0.6%)가 갈렸다.
- **예측 21개 가운데 18개가 맞았다.** 틀린 셋은 모두 4 KiB의 비용 한도다.

## 한계

- 복원 뒤 되살린 rank가 짝 rank의 증분 체크포인트를 모두 거절해 짝 rank의 보호가 사라진다(둘째 죽음은 되살리지 못할 것). 전체 이미지를 새 기반으로 다시
  받는 단계가 다음 작업이다.
- 장애는 SIGKILL 하나뿐이고 동시 다중 죽음, 복원 중 죽음, 노드 고장은 다루지 않았다. application은 결정성 요구(단일 대입, 신호 문턱에만 기대는 분기,
  GIN만)를 지켜야 하고, 원본 버퍼를 상대의 다음 확정 체크포인트까지 바꾸지 않아야 한다.
- 같은 노드 상대의 죽음을 FIN 대신 RST로 받으면(죽을 때 읽지 않은 자료가 있으면) 감지가 약 1 s 늦다. 비용은 시험 프로그램의 put이고 실제 학습의 단계
  시간은 재지 않았다.
