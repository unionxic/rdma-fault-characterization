# pair_reset: 장애 난 QP 쌍만 재설정

GIN 투명 복구는 장애가 나면 상대와의 모든 GIN 문맥 QP(이 설정에서 4개)를 다시 세운다. 장애 난 문맥의 QP 쌍만 다시 세우게 고치고,
측정 전에 고정한 예측으로 쟀다(태그 `prereg/gin-pair-reset-v1`). 진행 기록은 [EXPERIMENT.md](EXPERIMENT.md)에 있다.

## 무엇을 쟀나

- **바꾼 것:**
  - 복구 요청에 범위(장애 난 문맥)를 실어 두 rank가 그 쌍만 다시 세운다.
  - 좁힐 수 없을 때(다른 문맥도 고장, 범위 충돌, 스위치 끔)는 전체 재설정으로 돌아간다.
- **잰 것:** 판정 100회, 지연 20회.
  - 두 문맥에 동시에 트래픽을 흘리는 드라이버 모드를 새로 만들었다. 한 문맥만 고장 내고, 다른 문맥이 멈추는지 봤다.
  - 같은 hold에서 전체 재설정(스위치 끔)과 시간을 비교했다.

## 결론

- **복구가 약 4분의 1로 빨라졌다.** 같은 hold에서 견줬다.
  - 시작 쪽 Commit 중앙값: 3 315 µs에서 768 µs로.
  - 라운드 전체: 11 379 µs에서 3 013 µs로.
- **다른 문맥은 멈추지 않았다.**
  - 전체 재설정에서는 다른 문맥이 10.7–11.5 ms 묶였다(5/5).
  - 좁힌 복구에서는 그동안에도 계속 돌았고, 가장 긴 반복이 10.7–12.3 µs로 장애 없는 수준이었다(20/20).
- **좁힐 수 없는 경우는 전체 재설정으로 돌아가 투명하게 복구했다.** 모든 문맥 고장 10/10, 두 rank가 다른 범위로 동시에 시작한 경우 10/10.
- **응답 쪽의 다른 고장 난 QP를 남길 수 있다.**
  - 상대 QP 오류에서 상대의 QP 4개가 모두 오류였는데, 문맥 0 쌍만 복구하고 나머지 3개는 오류로 남았다(5/5).
  - 그 문맥을 다음에 쓰면 약 3.5 s 기다린 뒤 다시 복구된다.
  - 이 실험의 셀은 문맥 0만 써서 판정에는 영향이 없었다.
- 예측 23개가 모두 맞았다. 기존 회귀 칸과 장애 없는 지연은 그대로였다.

## 한계

- 범위는 시작 쪽의 QP만 보고 정한다. 응답 쪽은 자기 QP를 확인하지 않아 위와 같이 고장 난 QP를 남길 수 있다.
- 다른 문맥이 멈추지 않았다는 것은 그 문맥이 링크를 쓰는 간격(약 0.5 ms) 단위로만 보인다.
- 두 rank가 같은 문맥 번호를 쓴다는 전제가 있다. 2 rank, 문맥 4개, 노드 한 쌍이다.
