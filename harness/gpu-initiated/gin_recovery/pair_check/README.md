# pair_check: 쌍 재설정에서 응답 쪽의 자기 QP 확인

장애 난 QP 쌍만 다시 세우는 복구는 범위를 시작 쪽의 QP만 보고 정해서, 응답 쪽의 다른 고장 난 QP를 오류 상태로 남길 수 있었다. 응답 쪽도
좁힌 복구 요청을 받으면 자기 QP를 먼저 확인하고, 범위 밖에 고장 난 QP가 있으면 거절해 전체 재설정으로 다시 돌게 고쳤다. 측정 전에 고정한
예측으로 쟀다.

## 무엇을 쟀나

- **바꾼 것:**
  - 응답 쪽이 범위 밖 QP의 상태를 확인하고, 정상이 아니면 거절한다.
  - 시작 쪽은 거절을 받으면 전체 재설정으로 다시 돈다.
  - 범위 충돌 뒤에는 범위를 다시 정하게 했다.
- **잰 것:** 판정 110회, 지연 20회.
  - 상대의 QP가 모두 고장 난 경우, 응답 쪽의 쉬는 QP 하나가 이미 고장 난 경우, 응답 쪽이 깨끗한 경우, 범위 충돌.
  - 확인을 끈 대조와 이전 빌드 기준을 같은 측정 시간대에 섞어 돌렸다.

## 결론

- **고장 난 QP가 남지 않았다.** 응답 쪽이 좁힌 복구를 거절했고, 전체 재설정으로 다시 돌아 투명하게 복구됐다. 끝날 때 두 rank의 QP는 모두
  정상이었다. 확인을 끄면 예전처럼 응답 쪽 QP 3개가 오류로 남았다.
- **응답 쪽이 깨끗하면 좁힌 복구가 그대로 유지됐다.** 확인에 약 0.23 ms가 들었고, 장애 없는 지연은 같았다.
- **범위 충돌 뒤 다시 좁히는 예측은 틀렸다.** 다시 정한 쌍 복구가 또 충돌해 전체 라운드 하나로 합쳐졌다. 결과는 투명했고 QP는 모두 정상이었다.
  충돌 때는 확인이 늘 거절하는 구조라, 이 설계로는 다시 좁힌 라운드가 나올 수 없다.
